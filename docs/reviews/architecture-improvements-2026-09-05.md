## Findings resolved during review

1. A first-registration race could allow two finalization writers. Finalization now owns a single in-flight operation before registration awaits; a dedicated race test holds registration open and verifies one writer.
2. A cold DO with only a deletion fence could accept sequence zero. Cold admission now checks the fence before creating recording state; the real SQLite regression rejects the append.
3. Background live history could finish after a new selection or connection and decode into the wrong view. History reads now carry cancellation and generation checks; idle review reads into an isolated host and adopts only the current selection.
4. Live handoff could lose the selected tab or publish incomplete saved checkpoint choices. Handoff retains the active event-store tab and republishes choices after following stops.
5. Separately minified SDK worker code could disagree with the host about private property names. The self-contained worker is generated inside the same minification step; each shipped bundle is tested with a real standalone worker and malformed optional-event accounting.
6. Replay content existed in the DOM but was clipped by its card. Horizontal scroll viewports inherited the whole card height, and the minimum stage height expanded its width. Local auto-height/explicit-width fixes and browser bounds assertions now protect the visible recording, controls, and masking caption. Multi-tab breadcrumbs also use their real navigation times instead of adding an invented entry at session start.

## Lint warning follow-up

The six baseline warnings were resolved after the architecture review. Five came from `packages/rrweb-fork/tsconfig.json` disabling null checks required by a type-aware lint rule. Null checks are now enabled. This exposed a test callback inferred as returning `undefined`; its explicit `() => void` type now matches the Promise resolver it stores. The remaining warning came from the restart test caching `publicMirror.getId` without binding its receiver. It now binds the method while still capturing it before the recording restarts, preserving the regression check against a stale mirror.

The impact is limited to type checking, two test declarations, and documentation. Runtime recorder code, storage, backend logic, API fields, frontend consumers, and user interactions are unchanged, so no new browser or deployment path requires validation. Root `vp check` reports zero warnings, lint errors, or type errors; no rule was disabled or suppressed. The full regression suite passes all **1,766 tests across 227 files**. Review result: pass, with no unresolved lint finding.
