# Official dependency upgrades — 2026-09-06

The requested official-only upgrade is implemented and verified locally. This is **partial security remediation**, not a claim that every bundled dependency is free of known issues. No production deployment was run.

## Scope and decisions

The audit checked all **56 external direct npm package names across 10 workspaces**, the complete npm dependency lock, and the analytics container. **32 direct package names were upgraded**. See the [complete direct-package inventory](official-dependency-inventory-2026-09-06.md) for every selected or retained version and its reason.

Work started from `b23ca6c` in a separate checkout. The already committed replay-controls change, `98e0752`, was then brought in before the final checks. Unrelated work in the original checkout was preserved. The original dashboard development server was temporarily replaced on port 8899 for the upgraded app checks, then restored on that same port.

Changes were made in this order:

1. **Security fixes in development tools:** Vite+ and its official core alias move together to 0.3.0, bringing Vitest, Browser and Mocker 4.1.11. The official compatible parent updates also resolve fast-uri 3.1.7, brace-expansion 5.0.9, minimatch 10.2.6, PostCSS 8.5.28, nanoid 3.3.18 and Browserslist 4.28.9.
2. **Runtime and package-manager alignment:** Cloudflare's Node pin and the minimum engine move to 22.23.2; pnpm moves within its existing major to 11.25.0. Setup guidance uses the installer's PATH instead of assuming Vite+'s old installation location. The `doctor` script now runs the checked, locked React Doctor release.
3. **Compatible application releases:** React/React DOM, Better Auth, Base UI, TanStack, Sentry, Motion, Tailwind, rrweb, icons and supporting packages move in matched families. Major framework migrations remain separate. No database schema, API response, authentication policy, SDK event format or UI source behavior was changed by this upgrade.
4. **Official analytics libraries:** Python 3.12.14, pip 26.2.1, PySpark 3.5.9, Java 17 Bookworm security updates, and matched Iceberg runtime/AWS 1.10.2 JARs. The image digest and both downloaded JAR checksums were checked against their publishers. Individual bundled Java libraries were not replaced.

The existing Vite alias remains the only dependency override. No package patch, new fork, build-script permission or release-age bypass was added. Obsolete release-age exceptions were removed; the 24-hour cooldown remains. The root now explicitly declares Happy DOM through the shared catalog because the root owns the Vitest environment. Without it, Vitest independently resolves a newer optional peer even when the application manifests specify the compatible release.

Vite+ generated its updated command guidance in `AGENTS.md` and `CLAUDE.md`. Its formatter also changed whitespace in five existing files, including three vendored rrweb files. TypeScript emits byte-identical JavaScript before and after those five edits. The existing recorder fork was not re-synced or given a new third-party bug patch.

## Findings and releases held back

1. **Cloudflare's current parent releases still contain 11 upstream advisories.** Latest Wrangler 4.129.0 and Cloudflare Vite plugin 1.54.4 select Miniflare 5.20260903.0-alpha, which pins Sharp 0.35.2 and Undici 7.29.0. Their official fixes are [Sharp 0.35.4](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c) and [Undici 7.29.1](https://github.com/nodejs/undici/releases/tag/v7.29.1). The remaining count is **3 high, 5 moderate and 3 low**. These are development/deployment-tool dependencies; they are not evidence of an exploitable production Worker route. Removing them now would require an override or a custom parent package, which the user declined.
2. **The analytics container retains bundled dependency advisories.** npm audit does not cover Python, Java, shaded JARs or Debian packages. The [container review](official-dependency-container-security-2026-09-06.md) and [complete evidence map](official-dependency-container-security-2026-09-06.json) cover 454 Maven coordinates and 94 Debian source packages. They retain 112 Maven advisory matches (including 4 critical) and 172 Debian source-package/CVE matches, with important application-exposure distinctions. The most direct remaining application path is Iceberg's classic REST HTTP client; no verified official parent upgrade clears all its findings. Python distributions have no OSV matches after the pip upgrade. No clean-container or universal-exploitability claim is made.
3. **A canvas seek ordering defect already exists in the published player.** The first browser run passed 15/16 cases but one ESM canvas case stayed red after seeking to the later green frame. Both recorded bitmap events were present. rrweb 2.1.0 and 2.1.1 ship byte-identical ESM/CJS, maps, CSS and declarations (ESM SHA-256 `9d31b87f3ada744003f2eb8dd05d04c1513cf11b5874aecfcd86e4fd07a4aaa7`). A controlled execution of their exact bitmap functions reproduced the stale frame in both versions when the old bitmap completed last. The original trace did not record decode completion order, so that run's precise trigger remains unconfirmed. Five focused repeats and the final 27-case suite pass; they do not establish that the existing defect is fixed. The final-green assertion was retained and no local rrweb patch was added. [Playwright 1.62](https://playwright.dev/docs/release-notes#version-162) changes Chromium 149 to 151, which may expose different scheduling.
4. **Happy DOM 20.12+ is rejected for this suite.** Version 20.14.0 produced 20 unhandled `AbortError`s while assertions passed. The upstream [animation cancellation issue](https://github.com/capricorn86/happy-dom/issues/2339) remains open; 20.11.15 removes the errors without suppression or a patch. Both tooltip tests pass (13 assertions), followed by the full clean suite. This selected version is beyond the published Happy DOM security fixes.
5. **Iceberg 1.11.0 is held.** Its [reported REST-vended credential refresh regression](https://github.com/apache/iceberg/issues/17810) affects the integration style used here. The matched 1.10.2 runtime/AWS release avoids that new path. No undocumented flag or credential workaround was added.

The original **21 npm audit findings** are cleared. The external author-advisory check also caught and resolved additional fast-uri and Vitest findings that the initial npm report did not list. In particular, the newer [Vitest mocker advisory](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9) requires 4.1.11; stopping at 4.1.10 would have been incomplete.

The container fixture initially over-specified one behavior: it demanded no session snapshot during an event-only late-arrival deletion. The existing runner deliberately sends DELETE to both data tables, and an empty DELETE can create metadata. The final test now proves that any such snapshot changes no data-file entries or bytes, that event-only maintenance makes no further session change, and that a true second zero check creates no snapshot. Both modes observed one empty late session snapshot. The production purge code was not changed to satisfy the test.

## Limits and verdict

**Local build, test, browser and old-to-new data compatibility checks pass. Security remediation remains partial.** The official-only policy is preserved and no new application regression was established; the existing intermittent canvas defect remains a reported limitation.

The disposable Hadoop fixture proves local Spark/Iceberg deletion and file behavior. It does **not** prove Cloudflare REST catalog negotiation, R2-vended credentials, Pipelines delivery, live D1 scheduling or a production container rollout. GitHub OAuth was checked through redirect creation and session behavior, not a real external sign-in. Those external checks remain required before claiming the upgraded analytics image is production-verified. No deployment, production deletion, advisory suppression or custom dependency patch was performed.
